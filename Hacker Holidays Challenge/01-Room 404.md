# Room 404

This is the CTF room from day 2 of the Hacker Holidays challenge. It is rated easy, with an estimated completion time of 30 minutes.

> **TryHackMe Room:** [Room 404](https://tryhackme.com/room/hh-room404-804573bf)

The room covers two main themes: directory enumeration, and finding exposed code inside a hidden directory.

## Directory Enumeration

I first used `gobuster` to enumerate hidden directories. Once I discovered the hidden path, I navigated to it and downloaded its contents locally so that I could analyze the structure and files offline.

## Finding the Flag Through the Exposed Artifacts

The hidden directory contained multiple objects, and all the other artifacts pointed toward one particular object. Because it could not be read with a normal text editor, I decompressed it with `python3`, using the following command:

```bash
python3 -c "import zlib; print(zlib.decompress(open('<Object name>', 'rb').read()))"
```

The flag was not in that object, so I continued with the next one, where I found it.

## Conclusion

When I took part in the original Hacker Holidays challenge, I was relatively new to Capture the Flag (CTF) rooms, and this one was not easy for me. It did teach me how dangerous it is when version control metadata is accidentally left exposed on a live server.

Months later, I decided to redo some of these rooms for my portfolio. After completing many more CTFs since then, this room felt easy, although I have yet to encounter another room that exposes a `.git` directory. In real-world web development, this mistake happens when entire project folders are copied to a server through raw FTP or deployment scripts instead of being properly packaged. Developers can prevent it by configuring their web servers (such as Nginx or Apache) to block access to all hidden dotfiles, and by ensuring that deployment pipelines strip out internal repository data.
